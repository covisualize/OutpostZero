# Asset pipeline

Every model in `Assets/Models` is generated by Python scripts in `BlenderScripts/`, exported as FBX, and turned into a prefab and material by Unity on import. Nothing is modelled by hand, so any model can be rebuilt from source.

```
BlenderScripts/generate_*.py  ->  Assets/Models/<Category>/<Name>.fbx
                               ->  Assets/Models/<Category>/<Name>_{Albedo,Normal,AO,Mask,Icon}.png (+ .meta)
Unity import (FbxPrefabPostprocessor)
                               ->  Assets/Materials/Baked/<Name>.mat   (OutpostZero/TriplanarRim)
                               ->  Assets/Prefabs/<Category>/<Name>.prefab (collider added)
```

## Manifest

`BlenderScripts/assets.manifest.json` records the pipeline settings and every committed model:

| Field | Meaning |
|---|---|
| `blender` | Blender version the set was built with (`4.2.x`; the build refuses anything older than 4.2) |
| `axis` | FBX export axes: `{"forward": "-Z", "up": "Y"}` |
| `export` | FBX scale mode (`FBX_MESH`) |
| `textures` | Maps baked beside each FBX: `Albedo`, `Normal`, `AO`, `Mask`, `Icon` |
| `textureSize` | Map resolution in pixels (128) |
| `categories` | Model folders: `Characters`, `Weapons`, `Environment`, `Props`, `BaseBuilding` (plus `Kit`) |
| `assets` | Repo-relative path of every FBX, e.g. `Assets/Models/Props/Prop_StreetLamp.fbx` |

`generate_kit.register_manifest()` rewrites the `Kit/` entries when the snap kit is rebuilt. For every other category, add the path by hand when you add a model. `test_manifest.py` fails if a listed FBX is missing, lacks UVs, or is a character without the `Hips` bone.

Per-asset generator ids, tags and incremental hashing (PRO-46) are not in the manifest yet; the list above is the whole schema today.

## Generator contract

A generator is a no-argument function in one of the category modules:

| Module | `--only` name | Output folder |
|---|---|---|
| `generate_characters.py` | `characters` | `Characters` |
| `generate_weapons.py` | `weapons` | `Weapons` |
| `generate_architecture.py` | `architecture` | `Environment` |
| `generate_props.py` | `props` | `Props` |
| `generate_kit.py` | `kit` | `Kit` |
| `generate_base_building.py` | `base` | `BaseBuilding` |

Each generator:

1. Calls `blender_utils.reset_scene()`.
2. Builds geometry with the `create_box`, `create_cylinder`, `create_cone` and `create_sphere` helpers, and gives each part a material from `get_or_create_material(name, colour, metallic, roughness)`.
3. Joins the parts with `join_objects(parts, "<AssetName>")` and calls `set_origin_to_bottom` so the pivot sits on the floor.
4. Characters also call `prepare_character` / `attach_humanoid` to add the humanoid armature and keyed clips.
5. Calls `export_fbx(os.path.join(MODELS_DIR, "<AssetName>.fbx"), animated=...)`. This unwraps UVs, exports with the manifest axes, and writes the texture set through `texture_set.write_set`.

`build_all_assets.py` lists every generator per category in `phases`. A generator that raises marks the build failed, but the remaining generators still run.

## Naming

| Thing | Pattern | Examples |
|---|---|---|
| Model | `<Category>_<Name>[_<Variant>]` | `Prop_Barrel_Toxic`, `Weapon_Pistol_9mm`, `Zombie_Brute`, `Base_Generator_Diesel`, `Building_Warehouse_Depot` |
| Kit piece | `Kit_<piece>` (lower-case piece id from `kit_catalog.py`) | `Kit_plywood_door`, `Kit_balcony` |
| Material (Blender) | `Mat_<Family>_<Variant>` | `Mat_Dumpster_Rust`, `Mat_Concrete_Weathered` |
| Texture | `<ModelName>_<Map>.png` | `Prop_Dumpster_Albedo.png`, `Prop_Dumpster_Mask.png` |
| Baked material (Unity) | `Assets/Materials/Baked/<ModelName>.mat` | `Prop_Dumpster.mat` |
| Prefab | `Assets/Prefabs/<Category>/<ModelName>.prefab` | `Assets/Prefabs/Props/Prop_Dumpster.prefab` |

Model prefixes in use: `Survivor_`, `Zombie_`, `NPC_`, `Colonist_`, `Weapon_`, `Loot_`, `Road_Tile_`, `Building_`, `Ruin_`, `Barricade_`, `Vehicle_`, `Prop_`, `Kit_`, `Base_`.

## Units, pivots and scale

- 1 Blender unit = 1 metre = 1 Unity unit. Export uses `global_scale=1.0`, `apply_unit_scale=True` and `FBX_SCALE_ALL`, so Unity imports at scale 1.
- Y is up and -Z is forward in Unity (`axis_up='Y'`, `axis_forward='-Z'`, `bake_space_transform=True`).
- Pivot at the bottom centre (`set_origin_to_bottom`), so models sit on the ground at y = 0.
- Kit pieces snap to a 2 m grid (`kit_catalog.GRID`); door openings are 1.2 m clear.

## Textures

`texture_set.py` bakes the five maps procedurally from the model name, so a rebuild reproduces them exactly. It writes PNGs with hand-written `.meta` files (sRGB albedo and icon, linear normal, AO and mask), with stable GUIDs derived from the path. To rebake every map without Blender, run:

```bash
python3 BlenderScripts/texture_set.py
```

## Unity import

`Assets/Scripts/Editor/FbxPrefabPostprocessor.cs` handles anything under `Assets/Models/`:

- Cameras and lights are dropped. Materials are imported via material description.
- Characters (`/Characters/`) get a Generic rig with an avatar created from the model, and uncompressed animation. Their clips are handed to `SurvivorAnimatorBuilder.AssignMotions`, which binds them into `Resources/SurvivorLocomotion.controller`. Other models import without animation.
- If `<Name>_Albedo.png` exists, a `OutpostZero/TriplanarRim` material is created or updated with albedo, normal, occlusion and mask maps.
- A prefab is created the first time the model is imported. If the model has no collider, the prefab gets a `BoxCollider` fitted to its renderer bounds. Existing prefabs are never overwritten, so hand edits survive re-imports.

## Levels of detail and colliders

- There are no mesh LOD chains yet. `Graphics/LodGovernor` hides distant kit blocks and street clutter at runtime and keeps skyline cards. `PerfBudget` logs when frame time (16.6 ms) or the alive-zombie cap is exceeded for several frames.
- Colliders are a fitted `BoxCollider` per prefab. `PrototypeSceneBuilder` adds mesh or box colliders to scene-placed models. Characters use a `CharacterController` or NavMesh agent instead.

## Triangle budgets

`asset_audit.py` (run by `test_asset_audit.py`) checks every manifest entry for the five maps, UVs, and a triangle budget:

| Folder | Max triangles |
|---|---|
| `Characters` | 6000 |
| `Props`, `Weapons` | 2000 |
| `Kit` | 1500 |
| `Environment`, `BaseBuilding` | 8000 |

## Adding a new asset end to end

1. Write `generate_<thing>()` in the right category module, following the generator contract, and name the output by the naming table.
2. Add `("<AssetName>", module.generate_<thing>)` to that category in `build_all_assets.py`.
3. Add `Assets/Models/<Category>/<AssetName>.fbx` to `assets` in `assets.manifest.json` (kit pieces are registered automatically).
4. Build just that category:

   ```bash
   blender -b -P BlenderScripts/build_all_assets.py -- --only props
   ```

   ```powershell
   & "C:\Program Files\Blender Foundation\Blender 4.2\blender.exe" -b -P BlenderScripts\build_all_assets.py -- --only props
   ```

5. Run the checks that need no Blender:

   ```bash
   cd BlenderScripts && python3 -m unittest test_paths.py test_manifest.py test_character_rig.py test_texture_set.py test_kit_catalog.py test_character_detail.py test_asset_audit.py
   ```

6. Open Unity. The postprocessor creates the material and prefab. Reference the model from `ModelPaths` or place it through `PrototypeSceneBuilder`, then rebuild the arena (**Tools > Outpost Zero > Build Prototype Test Arena**).
7. Commit the FBX, the five PNGs and their `.meta` files, the manifest change, and the generated prefab and material.
